# Implementation Plan: CarServ Pro — Multi-Tenant Car Service SaaS Platform

**Branch**: `001-carserv-pro-platform` | **Date**: 2026-03-04 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-carserv-pro-platform/spec.md`

## Summary

Build a multi-tenant SaaS platform for car service businesses (PPF, ceramic coating, tinting, detailing) with two main interfaces: a customer-facing PWA website (service browsing, cart, reservations) and an admin dashboard (reservation management, invoicing with ZATCA Phase 1 compliance, accounting, business settings). Fully bilingual Arabic (RTL default) / English, dark/light mode, Firebase-only backend with Firestore security rules enforcing tenant isolation. Single Cloud Function for payment webhook handling.

## Technical Context

**Language/Version**: TypeScript 5.x, React 18, Node.js 20 (Cloud Functions only)
**Primary Dependencies**: React 18 + Vite 5, shadcn/ui, Tailwind CSS 3, Firebase SDK v10 (Firestore, Auth, Storage, FCM), Vite PWA Plugin (vite-plugin-pwa), react-i18next, Zustand, React Hook Form + Zod, React Router v6, qrcode (QR generation), html2pdf.js or jspdf (PDF export), date-fns + @date-fns/hijri or hijri-converter (Hijri dates)
**Storage**: Firebase Firestore (NoSQL), Firebase Storage (images/receipts)
**Testing**: Vitest + React Testing Library, Firebase Emulator Suite for integration tests
**Target Platform**: Web (PWA) — mobile browsers + desktop browsers, installable via PWA
**Project Type**: Web application (SPA with PWA capabilities + 1 Cloud Function)
**Performance Goals**: <3s initial load on 3G (SC-006), <1s language switch (SC-005), <3min reservation flow (SC-001)
**Constraints**: Offline-capable app shell (PWA), no separate backend server (except 1 Cloud Function for TC-012), all Firestore ops scoped to `tenants/{tenantId}/`, Arabic RTL as default, ZATCA Phase 1 only
**Scale/Scope**: Single tenant initially (multi-tenant architecture designed), ~30+ screens/views, ~15 Firestore collections

**Structure Decision**: Single project with a top-level `src/` for the React SPA and a separate `functions/` directory for the isolated Firebase Cloud Function (payment webhook only, per TC-012). This follows Firebase's recommended project layout and keeps the Cloud Function minimal and decoupled from the frontend.
